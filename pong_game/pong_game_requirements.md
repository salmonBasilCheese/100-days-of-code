# システム要件定義書: Pong Game (Day 22)

## 1. 主語・インターフェース (Actors, Dimensions & Interfaces)

### 1.1 画面構成 (Screen)
* **解像度**: 幅 800px × 高さ 600px
* **座標系**: 原点 `(0, 0)` を画面中央とするデカルト座標系
  * X軸: `[-400, 400]`（左端: -400, 右端: 400）
  * Y軸: `[-300, 300]`（下端: -300, 上端: 300）
* **背景色**: 黒 (`"black"`)
* **センターライン**: 画面中央 `x = 0` に、破線を描画（幅 2px、長さ 10px、間隔 10px の白線）。

### 1.2 オブジェクト仕様
* **パドル (Paddle)**:
  * クラス責任: 自身の描画、Y軸移動、可動域クランプ。
  * 物理サイズ: 幅 20px × 高さ 100px（Turtle標準サイズ `shape("square")` を `stretch_wid=5, stretch_len=1` に変形）。
  * 色: 白 (`"white"`)
  * 初期位置:
    * Player 1 (Left Paddle): `(-350, 0)`
    * Player 2 (Right Paddle): `(350, 0)`
  * 移動ステップ量: 20px / input tick
* **ボール (Ball)**:
  * クラス責任: 自身の移動、壁・パドルとの衝突時の反転・加速、リセット・サーブ管理。
  * 物理サイズ: 20px × 20px（円形、直径 20px、半径 $r = 10\text{px}$）。
  * 色: 白 (`"white"`)
  * 初期位置: `(0, 0)`
  * 初期移動ベクトル: `dx = 10.0`, `dy = 10.0`
  * 移動更新インターバル: 初期値 `0.05` 秒
* **スコアボード (Scoreboard)**:
  * クラス責任: 各プレイヤーのスコア加算、ヘッダー表示の描画更新、ゲーム終了時の勝者宣言。
  * 表示位置: `y = 200` 付近（Left: `(-100, 200)`, Right: `(100, 200)`）
  * 初期値: `l_score = 0`, `r_score = 0`
  * フォント: Courier, 40pt, bold

### 1.3 操作インターフェース
OSのキーリピート遅延に依存せず、同時押しおよび滑らかな移動を実現するため、キー押下状態を保持するイベントリスナーを採用する。
* **Player 1 (Left)**:
  * `W`: 上方向移動 (`y += 20`)
  * `S`: 下方向移動 (`y -= 20`)
* **Player 2 (Right)**:
  * `Up` (上矢印キー): 上方向移動 (`y += 20`)
  * `Down` (下矢印キー): 下方向移動 (`y -= 20`)

## 2. 境界制約 (Boundary Conditions & Invariants)

### 2.1 パドルの可動域クランプ
* 画面境界 `y = \pm 300` に対し、パドル半高（50px）を考慮した限界値を設ける。
* **パドル中心座標 $y$ の許容範囲**:
  $$-250 \le y \le 250$$
* 上限 `y >= 250` での上移動入力、下限 `y <= -250` での下移動入力は無視（クランプ）し、パドルが画面外へはみ出すことを禁止する。

### 2.2 上下壁の反射境界
* 上壁 (`y = 300`) および下壁 (`y = -300`) との衝突:
  * ボール半径 $r = 10$ を考慮した衝突判定:
    $$\text{上壁衝突}: y \ge 290 \implies dy \leftarrow -|dy|$$
    $$\text{下壁衝突}: y \le -290 \implies dy \leftarrow |dy|$$
  * 符号を絶対値から強制指定することで、壁の外側にめり込んだ際の連続反射（スタックバグ）を防ぐ。

### 2.3 パドルとの衝突境界（トンネリング防止・符号固定）
単純な点間距離判定 `distance()` ではなく、X座標・Y座標の矩形交差判定（AABB近似）を用いる。
* **右パドル (Right Paddle: $x = 350$, $w = 20$, $h = 100$)**:
  * 衝突条件: `ball.x >= 330` かつ `ball.x <= 360` かつ `abs(ball.y - r_paddle.y) <= 50`
  * 反射処理:
    $$dx \leftarrow -|dx| \times 1.05$$
    $$dy \leftarrow dy \times 1.05$$
    $$\text{move\_speed} \leftarrow \max(\text{move\_speed} \times 0.9, 0.01)$$
* **左パドル (Left Paddle: $x = -350$, $w = 20$, $h = 100$)**:
  * 衝突条件: `ball.x <= -330` かつ `ball.x >= -360` かつ `abs(ball.y - l_paddle.y) <= 50`
  * 反射処理:
    $$dx \leftarrow |dx| \times 1.05$$
    $$dy \leftarrow dy \times 1.05$$
    $$\text{move\_speed} \leftarrow \max(\text{move\_speed} \times 0.9, 0.01)$$
* **符号固定の不変条件**:
  * 右パドル反射時は必ず `dx < 0`（左向き）にする。
  * 左パドル反射時は必ず `dx > 0`（右向き）にする。
  * これにより、ボールがパドルの側面や内側にめり込んだフレームで連続バウンドする物理破綻を完全に遮断する。

### 2.4 最大速度制限（物理破綻防止ガード）
* ラリーごとに速度を上げるが、1フレームの移動量 $|dx|$ がパドル厚み（20px）を超えると「すり抜け（トンネリング）」が発生する。
* **速度上限制約**:
  * 1フレームの最大移動量: $|dx| \le 18.0$, $|dy| \le 18.0$
  * 最小スリープ時間: `time.sleep` の最小値を `0.015` 秒（約60FPS相当）で下限ガード。

## 3. 操作・ロジック仕様 (State Machine & Logic)

### 3.1 状態遷移 (State Machine)
システムは以下の4状態を持つステートマシンとして動作する。
1. `READY`: 初期化完了、画面描画、プレイヤーの初期配置。
2. `PLAYING`: ボール移動、入力受付、衝突判定ループ。
3. `POINT_SCORED`: 得点発生、スコア加算、リセットおよびサーブ準備。
4. `GAME_OVER`: 規定点（5点）到達、勝者表示、メインループ終了。

```
[READY] 
   |
   v
[PLAYING] <------------------------+
   |                               |
   +---> (得点判定: |x| > 390)      |
   |           |                   |
   |           v                   |
   |     [POINT_SCORED]            |
   |           | (スコア < 5)       |
   |           +-------------------+
   |           |
   |           v (スコア == 5)
   +-----> [GAME_OVER]
```

### 3.2 得点およびリセット・サーブ遷移仕様
* **Player 1 (Left) 得点条件**: `ball.x > 390`
  * `l_score += 1`
  * ボール位置を `(0, 0)` にリセット。
  * **失点側（Right）へのサーブ**: `dx` を正（右向き、$+10.0$）に初期化。`dy` はランダムまたは直前と反転。
  * 速度パラメータ（スリープ間隔）を初期値（`0.05` 秒）に完全リセット。
* **Player 2 (Right) 得点条件**: `ball.x < -390`
  * `r_score += 1`
  * ボール位置を `(0, 0)` にリセット。
  * **失点側（Left）へのサーブ**: `dx` を負（左向き、$-10.0$）に初期化。
  * 速度パラメータを初期値に完全リセット。

### 3.3 勝利条件と終了フロー
* どちらかのプレイヤーが **5点** に到達した瞬間に `GAME_OVER` へ遷移。
* ボールの更新を停止し、画面中央に `"PLAYER 1 WINS"` または `"PLAYER 2 WINS"` を描画。

## 4. 例外・非機能要件 (Robustness & Non-Functional Requirements)

### 4.1 パフォーマンス・描画制御
* **トレーサー制御 (`tracer(0)`)**:
  * 自動描画を無効化し、1フレームごとに全要素（パドル、ボール、スコア）の位置確定後、明示的に `screen.update()` を実行する。
  * 画面のリフレッシュレートは約30〜60FPSを維持し、ちらつき（フリッカー）を完全に防止する。

### 4.2 入力防御とフォーカス喪失対策
* **ウィンドウフォーカス保証**:
  * 起動時に `screen.listen()` を明示的に呼び出し、キーボードフォーカスをキャプチャする。
* **同時押し・排他制御**:
  * 2名のプレイヤーが同時にキーを押下・保持した場合でも、各パドルが独立して移動できるようイベントハンドリングを設計する。

### 4.3 異常終了のハンドリング
* ユーザーがウィンドウの「×」ボタンを押して閉じた場合に、Pythonインタプリタが `Terminator` 例外をコンソールに吐き出してクラッシュしないよう、メインループを `try-except (turtle.Terminator, tk.TclError)` で保護し、正常終了シーケンスを通す。
