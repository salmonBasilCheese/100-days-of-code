# システム要件定義書: Amazon Price Tracker with Discord Notification

## 1. システム概要
### 1.1 目的
本システムは、Amazon.co.jp上の指定商品ページをスクレイピングして現在価格および割引情報を取得し、ユーザーがあらかじめ定義した「目標価格以下」または「目標割引率以上」の購買条件を満たした場合に、Discord Webhookを介して即時アラート通知を行う自動価格監視バッチシステムである。

### 1.2 背景・設計方針
- **背景**: Udemy「100 Days of Code (Day 47)」における価格監視自動化をベースに、SMTP（電子メール）から即時性・保守性の高い「Discord Webhook」へ通知基盤を刷新。
- **アーキテクチャ方針**:
  - Pythonスクリプト自体は常駐無限ループを持たず、「起動時に1回価格を精査し、条件判定・通知を行って正常終了する」単一責務のCLIバッチとして設計する。
  - 定時実行はOSネイティブ機能（Windowsタスクスケジューラやcron、GitHub Actions）に委任する。
  - 機密情報（Discord Webhook URL等）や監視対象設定は、外部環境変数（`.env`）または構成設定ファイルに分離し、Git管理外とする。

## 2. 機能要件 (Functional Requirements)

| 機能ID | 機能名 | 詳細説明 | 期待される入力 / 出力 |
| :--- | :--- | :--- | :--- |
| **FR-01** | **構成情報ロード機能** | `.env` または設定ファイルから監視対象商品URL、目標価格（円）、目標割引率（%）、Discord Webhook URL、偽装ヘッダー設定を読み込み検証する。 | 入力: 環境設定ファイル<br>出力: 構成パラメータオブジェクト |
| **FR-02** | **Amazon HTMLスクレイピング機能** | 完全なブラウザ偽装ヘッダー（`User-Agent`, `Accept-Language` 等）を伴い、対象URLからHTML本文を取得する。503エラーやCAPTCHA検知時は適切に捕捉する。 | 入力: 商品URL、HTTPヘッダー<br>出力: 取得したHTML文字列 |
| **FR-03** | **価格・商品情報抽出・パース機能** | 複数のDOMセレクタをフォールバック走査し、商品名、現在価格、参考価格（割引前価格）を抽出。文字列（`¥`, `,`）を正規化し、数値（`int`）に変換する。 | 入力: HTML文字列<br>出力: 商品名、現在価格（数値）、割引率（数値） |
| **FR-04** | **購入条件判定機能** | 取得した現在価格が「目標価格以下」または「目標割引率以上」を満たしているかを論理評価する。 | 入力: 現在価格、目標価格、目標割引率<br>出力: 通知要否フラグ（Boolean） |
| **FR-05** | **Discord Webhook 通知機能** | 条件合致時、Discordのリッチ埋め込み（Embed）形式で商品名、現在価格、割引率、商品リンクを含む通知ペイロードを生成し、Webhook経由でPOST送信する。 | 入力: 商品情報、Webhook URL<br>出力: HTTP 204 No Content（送信成功） |

## 3. 非機能要件 (Non-Functional Requirements)

### 3.1 信頼性・耐障害性
- **Bot検知（CAPTCHA / 503）ハンドリング**:
  - Amazonが返す「Robot Check」画面（CAPTCHA）またはHTTP 503 Service Unavailableを検知した場合、強制クラッシュさせず `[Warning] CAPTCHA検知またはBot遮断が発生しました` とログ出力し、異常ステータスコードで安全に終了する。
- **リクエスト偽装**:
  - 日本語ロケール（`Accept-Language: ja,en-US;q=0.9,ja-JP;q=0.8`）および実ブラウザ準拠の `User-Agent` を必須ヘッダーとして送信する。
- **タイムアウト**:
  - HTTPリクエストには `timeout=15` 秒を義務付ける。

### 3.2 運用性・拡張性
- **ステートレスバッチ設計**:
  - プロセス内で `time.sleep(86400)` 等の長期ループを実行しない。タスクスケジューラでの1日1回（または指定間隔）の呼び出しを前提とする。
- **セレクタの冗長化**:
  - AmazonのHTML構造変動に対応するため、価格要素セレクタ（例: `.a-price .a-offscreen`, `#priceblock_ourprice`, `#priceblock_dealprice`, `.priceToPay span.a-offscreen`）を優先度順に順次評価する。

### 3.3 セキュリティ・機密情報管理
- **機密情報の完全隔離**:
  - Discord Webhook URLは外部に公開してはならない。`.env` に定義し、`.gitignore` に明記してリポジトリへの混入を遮断する。

## 4. データ仕様・制約

### 4.1 主要数値・パラメータ
| 項目 | 設定値 / 境界値 | 備考 |
| :--- | :--- | :--- |
| **対象ドメイン** | `https://www.amazon.co.jp/` | 日本Amazon |
| **HTTPタイムアウト** | `15` 秒 | 通信遮断対策 |
| **価格型制約** | `int` (日本円) | 小数点は切り捨て/非許容 |
| **割引率型制約** | `float` (%) | `(参考価格 - 現在価格) / 参考価格 * 100` |
| **条件判定式** | `現在価格 <= 目標価格` OR `割引率 >= 目標割引率` | いずれかを満たせば通知 |

### 4.2 文字列クレンジング規則
- 価格文字列から `¥`, `￥`, `,`, `円`, 前後の空白文字、非改行空白（` `）を正規表現で完全除去し、`int` へキャストする。

## 5. テスト仕様・受入基準 (Acceptance Criteria)

1. **スクレイピング受入検証**:
   - 任意の Amazon.co.jp 実商品URLから、商品名および現在価格が数値型として欠損なく取得できること。
2. **条件判定受入検証**:
   - 目標価格より高い場合は通知がスキップされ、ログのみ出力されること。
   - 目標価格以下（または目標割引率以上）に設定した場合、Discord チャンネルへ Embed 形式で即座にメッセージが着信すること。
3. **例外耐性受入検証**:
   - 不正な URL、ネットワーク断、CAPTCHA 画面受信時にトレースバックでクラッシュせず、終了コードとともに明確なエラーログが残ること。
4. **セキュリティ受入検証**:
   - `git status` において `.env` が Untracked に現れず、除外されていること。
