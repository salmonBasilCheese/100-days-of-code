# システム要件定義書: Internet Speed Complaint / Reporting Bot

## 1. システム概要
### 1.1 目的
本システムは、Selenium WebDriverを用いてSpeedtest.net（https://www.speedtest.net/）上でネットワーク速度（下り・上り・Ping値）を自動計測し、計測結果と指定された閾値（下り30Mbps、上り10Mbps、Ping 50ms）を比較判定した上で、指定のソーシャル/レポートサービス（https://app.100daysofpython.dev/services/y）へ自動ログインし、条件に応じたテンプレート文面を自動投稿するシステムである。

### 1.2 設計方針
- **認証情報の厳格な秘匿**:
  - 提供されたログイン認証情報（Email / Password）はソースコード内にハードコードせず、`.env` ファイルに隔離して `python-dotenv` 経由で読み込む。また、Git追跡から `.env` を完全に除外する（`.gitignore` 設定）。
- **計測完了の確実な同期**:
  - 固定待機（`time.sleep`）を排し、Speedtest のテスト実行（約40〜60秒）に伴うDOM変化（結果表示クラスの付与や値の確定）を `WebDriverWait` で検知する。
- **Cookie同意および突発広告モーダルの突破**:
  - Speedtestアクセス時に表示されるGDPR/Cookie同意ダイアログやフルスクリーン広告を安全に破棄・回避する。
- **投稿判定ロジックの厳密化**:
  - 数値抽出時に文字列から余計な空白や単位を除去し、`float` 型に変換して正確な比較判定を行う。

## 2. 機能要件 (Functional Requirements)

| 機能ID | 機能名 | 詳細説明 | 期待される入力 / 出力 |
| :--- | :--- | :--- | :--- |
| **FR-01** | **認証情報・環境変数の読み込み** | `.env` から投稿用アカウント情報（Email, Password）を安全に取得する。 | 入力: `.env` ファイル<br>出力: 認証環境変数 |
| **FR-02** | **Speedtest 実行と速度計測** | https://www.speedtest.net/ にアクセスし、「Go」ボタンを押下して下り（Download）、上り（Upload）、Ping（Latency）を計測・抽出する。 | 入力: なし<br>出力: `download_speed` (float), `upload_speed` (float), `ping` (float) |
| **FR-03** | **速度判定および文面生成** | 下り < 30.0Mbps または 上り < 10.0Mbps または Ping > 50.0ms の場合は「遅い場合」、それ以外は「早い場合」のテンプレートに実測値を埋め込んで投稿本文を生成する。 | 入力: 計測数値群<br>出力: 投稿用メッセージ文字列 |
| **FR-04** | **投稿サービス自動認証** | https://app.100daysofpython.dev/services/y にアクセスし、フォームにEmailとPasswordを入力してログインを確立する。 | 入力: 認証情報<br>出力: ログイン後ダッシュボード/投稿画面 |
| **FR-05** | **メッセージ自動投稿** | テキストエリアに生成した文面を入力し、送信ボタンを押下して投稿を確定する。 | 入力: 投稿メッセージ<br>出力: 投稿完了通知/フィード反映 |

## 3. 非機能要件 (Non-Functional Requirements)

### 3.1 セキュリティ
- 認証情報漏洩の防止: `.env` を利用し、リポジトリへの秘密情報のコミットを防止する。
- ブラウザのパスワード保存ポップアップ抑止: Chromeオプションでパスワードマネージャーを無効化。

### 3.2 堅牢性・耐障害性
- 計測タイムアウト対策: スピードテスト完了待機は最長90秒まで許容する。
- 広告・オーバーレイ回避: `safe_click`（JavaScriptクリックフォールバック）を実装。

## 4. 主要数値・境界値・データ制約

### 4.1 主要数値パラメータ
| パラメータ | 規定値 | 備考 |
| :--- | :--- | :--- |
| **ウィンドウ解像度** | `1440 x 900` px 以上 | Speedtestのレイアウト崩れ・ボタン不可視化を防止 |
| **速度計測待機タイムアウト** | `90` 秒 | テスト完了までの非同期待機時間 |
| **通常要素待機タイムアウト** | `15` 秒 | ログイン・投稿フォームのロード許容時間 |
| **下り速度判定閾値** | `30.0` Mbps | 30未満で遅いと判定 |
| **上り速度判定閾値** | `10.0` Mbps | 10未満で遅いと判定 |
| **Ping値判定閾値** | `50.0` ms | 50超で遅いと判定 |

### 4.2 考慮すべき境界値・例外エラー
1. **計測タイムアウト**: ネットワーク不調によりテストが完了しない場合の例外ハンドリング。
2. **広告・オーバーレイブロック**: テスト中または終了後に表示されるモーダルによる `ElementClickInterceptedException`。
3. **数値抽出失敗**: DOM内の数値が `---` や空文字の段階でパースしようとした場合の `ValueError` 防止。

### 4.3 データの制約
- 数値の正規化: 取得したテキストから `Mbps` や改行を除去し、`float` 型に変換して比較すること。
- メッセージフォーマット: 指定された英文テンプレートの `x` と `y` を計測した実測値で厳密に置換すること。

---

## 5. テスト仕様・受入基準

1. **速度計測受入**:
   - Speedtest.net で下り・上り・Pingが数値としてコンソールに出力されること。
2. **テンプレート分岐受入**:
   - 閾値条件（下り30Mbps未満、上り10Mbps未満、Ping 50ms超）に従い、正しい文面が生成されること。
3. **自動投稿受入**:
   - `services/y` へのログインが成功し、生成された文面が正常に送信されること。
