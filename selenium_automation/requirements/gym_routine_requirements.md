# システム要件定義書: Gym Routine Automation Bot

## 1. システム概要
### 1.1 目的
本システムは、ジムのクラス予約ポータルサイトを対象に、Selenium WebDriverを用いてユーザー認証、特定曜日（直近および毎週火曜日・木曜日）のクラス自動検索、予約処理、待機リスト（キャンセル待ち）判定、および「My Bookings」画面での予約確定検証を自律的かつ堅牢に実行する自動化ボットである。

### 1.2 背景・設計方針
- **認証の自動化**:
  - 提供されたテストアカウント（Student / Admin）を用いて安全かつ確実にログイン処理を実行する。
- **動的スケジューリングと日付計算**:
  - Pythonの `datetime` モジュールを用いて現在日時から直近の「火曜日」「木曜日」の日付を自動計算し、UI上のカレンダー・一覧と照合して特定する。
- **状態判定（予約済み / 満席・待機リスト / 空き）**:
  - 対象クラスが「予約可能（Book）」「待機リスト参加（Waitlist）」「既に予約済み（Booked / Cancel）」のいずれであるかをボタンの文言やクラス属性から厳密に識別し、重複予約や無効なクリックを防止する。
- **プロフェッショナルなネットワーク障害・待機制御**:
  - 通信遅延や一時的なHTTPエラー、DOM再描画による要素不整合に対し、明示的待機（`WebDriverWait`）とリトライ機構（指数バックオフまたは一定間隔再試行）を組み込む。

## 2. 機能要件 (Functional Requirements)

| 機能ID | 機能名 | 詳細説明 | 期待される入力 / 出力 |
| :--- | :--- | :--- | :--- |
| **FR-01** | **認証処理（自動ログイン）** | ログイン画面へアクセスし、指定された認証情報（Student: `student@test.com` / `password123` 等）を入力・送信してセッションを確立する。 | 入力: メールアドレス、パスワード<br>出力: ログイン後ダッシュボードまたはスケジュール画面 |
| **FR-02** | **対象曜日クラスの動的特定** | 現在日時を起点に「直近の火曜日」「木曜日」の日付を計算し、スケジュール一覧から合致するクラス要素を特定する。 | 入力: 目標曜日（Tue/Thu）、スケジュール一覧<br>出力: 該当クラスのWeb要素群 |
| **FR-03** | **クラス予約および待機リスト制御** | 対象枠の状態を判定し、「Book」であれば通常予約、「Join Waitlist」であれば待機リスト処理を行い、既に予約済みの場合はスキップする。 | 入力: 対象スロットのボタン要素<br>出力: 予約/待機リスト処理の実行結果 |
| **FR-04** | **ネットワークエラー・耐障害性ハンドリング** | ページロード遅延、一時的な接続断、`TimeoutException` に対して最大再試行回数まで安全にリトライする。 | 入力: ネットワーク例外、Timeout<br>出力: リトライ実行または安全なロールバック |
| **FR-05** | **My Bookings での予約検証** | 「My Bookings」ページへ遷移し、予約対象となった火曜・木曜のクラスが正しく一覧に反映されているかを照合・検証する。 | 入力: 予約日時・クラス名<br>出力: 予約成立確認ログ（Pass / Fail） |

## 3. 非機能要件 (Non-Functional Requirements)

### 3.1 信頼性・堅牢性
- **明示的待機の徹底**:
  - 固定の `time.sleep` への依存を排除し、`WebDriverWait` と `expected_conditions`（`element_to_be_clickable`、`visibility_of_element_located`）による同期待ちを行う。
- **DOM更新の追従**:
  - 予約ボタン押下後に発生する非同期更新やモーダル展開に対し、`StaleElementReferenceException` を抑止する再取得処理を実装する。

### 3.2 運用性
- 実行ログをコンソールに出力し、各ステップの成否（ログイン成否、特定された日付、予約結果、My Bookings検証結果）を可視化する。

## 4. 主要な数値・境界値・データ仕様

### 4.1 主要数値パラメータ
| パラメータ | 規定値 | 目的・備考 |
| :--- | :--- | :--- |
| **ウィンドウ解像度** | `1440 x 900` px 以上 | スケジュール表やサイドナビの折りたたみを防止 |
| **明示的待機タイムアウト** | `10.0 - 15.0` 秒 | ネットワーク遅延・SPA描画の許容時間 |
| **ネットワークリトライ回数** | `3` 回 | 一時的な接続エラー時のリトライ上限 |
| **リトライインターバル** | `2.0 - 5.0` 秒 | サーバー負荷を避ける待機インターバル |

### 4.2 考慮すべき境界値・例外エラー
1. **ステータス境界**:
   - ボタンが「Book」ではなく「Full」「Waitlist」「Already Booked」となっているケースの分岐網羅。
2. **日付跨ぎ・月跨ぎの境界**:
   - 月末・月初や年末年始における「直近の火曜・木曜」の計算ズレを防ぐため、`datetime.timedelta` による厳密な日付演算を使用する。
3. **多重クリック・モーダル衝突**:
   - 予約確定時のローディングオーバーレイや確認ダイアログによる `ElementClickInterceptedException` の回避。

### 4.3 データの制約・表記仕様
- **日付・曜日表記の正規化**:
  - システム側が `Tue, Sep 15` や `2026-09-15` など多様なフォーマットを持つ場合、正規表現または `strptime` で統一的な比較フォーマットへパースする。
- **認証情報の型**:
  - メールアドレスおよびパスワードはUTF-8文字列として前後の空白をトリム（strip）して投入する。

## 5. テスト仕様・受入基準 (Acceptance Criteria)

1. **ログイン受入**:
   - `student@test.com` でログインが正常に完了し、予約可能なスケジュール画面が表示されること。
2. **自動特定・予約受入**:
   - 直近の火曜日および木曜日のクラスが自動判別され、空き枠であれば予約ボタン、満席であれば待機リストボタンが押下されること（既予約なら重複予約しないこと）。
3. **My Bookings検証受入**:
   - 処理完了後に「My Bookings」画面を開き、予約したクラスが一覧に存在することが確認・出力されること。
