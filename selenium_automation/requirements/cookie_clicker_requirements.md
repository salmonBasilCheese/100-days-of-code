# システム要件定義書: Cookie Clicker Automation Bot

## 1. システム概要
### 1.1 目的
本システムは、Webブラウザゲーム「Cookie Clicker（https://ozh.github.io/cookieclicker/）」を対象に、Selenium WebDriverおよびJavaScript実行エンジンを用いて大クッキーのクリック速度を極大化させつつ、定期的に最適なアップグレードや生産設備（Store要素）を自動購入することで、指定制限時間（5分間）内におけるクッキー獲得数および1秒あたりクッキー生産数（CpS）の最大化を達成する完全自動化ボットである。

### 1.2 背景・設計方針
- **クリックオーバーヘッドの極小化**:
  - PythonおよびSelenium経由の標準的なDOMクリック命令はHTTP通信経由のオーバーヘッドが大きく、高速連打には不向きであるため、ブラウザコンテキスト内でネイティブJavaScript（`element.click()`）を直接評価・発火する手法を採用する。
- **動的アップグレード戦略**:
  - 5秒ごとに画面右側のStoreセクションを精査し、その時点でアンロックかつ購入可能な設備の中で「最も高価な要素」を特定して優先購入する。購入可能な資金が残る限り、即時かつ連続的に購入を試みる。
- **初回言語選択モーダルおよび再読み込みへの完全対応**:
  - ページ初回アクセス時に強制表示される言語選択ダイアログ（英語等）の検知・選択、およびそれに伴って発生する自動ページ再読み込み（リロード）を堅牢に待機・同期処理する。

## 2. 機能要件 (Functional Requirements)

| 機能ID | 機能名 | 詳細説明 | 期待される入力 / 出力 |
| :--- | :--- | :--- | :--- |
| **FR-01** | **ブラウザ環境初期化・画面最適化** | Chrome WebDriverを初期化し、ウィンドウサイズを1280x800以上（または最大化）に設定して対象URLへアクセスする。 | 入力: 対象URL、ブラウザ設定<br>出力: 初期化済みWebDriverインスタンス |
| **FR-02** | **初回言語選択・再読み込み同期** | 言語選択プロンプト（`#langSelect-EN` 等）の可視化を待機しクリックする。その後発生するDOMリロード・ローディング完了を明示的に待機する。 | 入力: WebDriver<br>出力: ゲーム本編DOMのロード完了確認 |
| **FR-03** | **超高速大クッキークリックループ** | メインループ内で大クッキー要素（`#bigCookie`）に対し、JavaScript実行経由で遅延なく連続クリックを送り続ける。 | 入力: 大クッキー要素参照<br>出力: 所持クッキー数の増加 |
| **FR-04** | **Store自動精査・最適設備購入** | 5秒タイマー満了時、現在「アンロック（unlocked）」かつ「購入可能（enabled）」な製品・アップグレード要素を逆順探索（高額順）し、可能な限り購入を反復実行する。 | 入力: Store内全プロダクト要素<br>出力: 設備の購入成立と生産力更新 |
| **FR-05** | **実行タイマー制御・最終成果出力** | 5分（300秒）が経過した時点でメインループを安全に脱出し、最終獲得クッキー数および1秒あたり獲得クッキー数（CpS）を取得してコンソールに出力後、ブラウザを終了する。 | 入力: 経過時間計測<br>出力: 最終リザルトログ、セッション終了 |

## 3. 非機能要件 (Non-Functional Requirements)

### 3.1 信頼性・耐障害性
- **StaleElementReferenceException の完全抑止**:
  - 購入処理やクッキー獲得に伴い、StoreのDOM構造は頻繁に書き換えられる。購入ループ処理時は要素の参照をキャッシュせず、毎回セレクタ再探索または要素存在確認を挟む設計とする。
- **明示的待機の適用**:
  - ゲーム初期化や言語切り替え時の同期待ちには `time.sleep` による固定待ちを極力排し、`WebDriverWait` と `expected_conditions` による動的状態同期を行う。

### 3.2 性能・効率性
- **非ブロッキング時間管理**:
  - ループ内の時間計測は `time.time()` によるエポック秒の差分計算を採用し、Store判定中もタイマーのドリフト（ズレ）が発生しない構造とする。

## 4. 主要な数値・境界値・データ仕様

### 4.1 主要数値パラメータ
| パラメータ | 規定値 | 目的・備考 |
| :--- | :--- | :--- |
| **ウィンドウ解像度** | `1280 x 800` px 以上 | Storeおよびクッキー描画領域の不可視化を防止 |
| **Store確認インターバル** | `5.0` 秒 | 最適投資判定の周期 |
| **総実行制限時間** | `300.0` 秒 (5分) | テスト終了・リザルト集計タイミング |
| **暗黙的/明示的待機タイムアウト** | `15` 秒 | 初期ローディングおよび再読み込み同期許容時間 |

### 4.2 考慮すべき境界値・例外エラー
1. **言語選択と画面リロードの境界**:
   - 言語選択ボタン押下直後にDOM要素を探索すると、リロードによってセッションが無効化されるため、`staleness_of` または新DOMの特定要素表示まで確実に待機する。
2. **購入可能判定の境界**:
   - クッキー所持数が「価格とちょうど同額」の場合、内部処理の微小なラグで購入不可扱いとなるケースを考慮し、Store要素のクラス名（`enabled`）の付与状態を直接判定基準とする。
3. **無効な要素クリック**:
   - 非活性（`disabled`）要素の誤クリックによる例外停止を防ぐ。

### 4.3 データの制約・表記パース仕様
- **数値フォーマット変化の吸収**:
  - 所持クッキー数や価格表記は `1,000` 形式のカンマ表記から、後半は `1.5 million`, `2 billion`, `3 trillion` などの単位文字列を含む形式へ遷移する。
  - パース処理では正規表現を用いてカンマを除去し、各英語単位に対応する指数（million: $10^6$, billion: $10^9$, trillion: $10^{12}$）を掛け合わせて `float` / `int` に正規化する。

## 5. テスト仕様・受入基準 (Acceptance Criteria)

1. **初期化受入**:
   - スクリプト起動後、言語選択画面が自動突破され、ゲームプレイ画面が安定描画されること。
2. **クリック受入**:
   - 大クッキーが途切れることなく高速連打され、画面上でクッキー数が増加し続けること。
3. **Store自動購入受入**:
   - 5秒ごとにStoreが確認され、購入可能な最高価格の設備（カーソル、グランマ、ファーム等）が自動購入されること。
4. **完走受入**:
   - 例外クラッシュすることなく300秒間連続稼働し、終了時に最終クッキー数およびCpSが正しくログ出力されること。
