# システム要件定義書: Tinder Web Automation Bot

## 1. システム概要
### 1.1 目的
本システムは、Web版Tinder（https://tinder.com/）を対象に、Selenium WebDriverを用いてユーザーインターフェース上のスワイプ操作（Like / Dislike）、動的ポップアップ処理、および無料枠上限（Like制限）の検知を検証・学習するための自動化スクリプトである。

### 1.2 背景・設計方針
- **規約・法的リスクの最小化**:
  - Tinderの利用規約（Terms of Service）における自動化ツール規制を厳格に遵守するため、プライベートAPIへの直接リクエストは行わず、ブラウザUI上の通常操作をシミュレートする。
  - アカウント停止（シャドウバン・BAN）を回避するため、機械的な定速操作を排除し、人間らしいランダムな思考・インターバル待機を挟む。
- **動的ポップアップ・モーダルの確実なハンドリング**:
  - 位置情報許可、通知許可、ホーム画面追加、スーパーライク確認、マッチング成立モーダルなど、不定期に前面へ割り込む各種オーバーレイを検知・処理する。
- **Like制限（有料化プロンプト）の検知と安全停止**:
  - 無料プランにおける1日のLike上限到達時に表示されるモーダルを検知し、スクリプトを安全かつ速やかに終了する。

## 2. 機能要件 (Functional Requirements)

| 機能ID | 機能名 | 詳細説明 | 期待される入力 / 出力 |
| :--- | :--- | :--- | :--- |
| **FR-01** | **ブラウザ環境初期化** | 指定された解像度（デスクトップ標準またはモバイルビューポート）でChromeを起動し、Tinder Webへアクセスする。 | 入力: 起動オプション<br>出力: 初期化済みWebDriver |
| **FR-02** | **初回各種プロンプトの突破** | 位置情報・Cookie承諾・通知許可などの初期モーダルを検知し、「許可」または「後で（Not interested / Allow）」をクリックしてスワイプ画面へ到達する。 | 入力: 初期モーダル要素<br>出力: カードスタック表示画面 |
| **FR-03** | **スワイプ実行エンジン (Like/Nope)** | キーボード操作（矢印キー `RIGHT`/`LEFT`）または画面ボタン（Heart/Cross）を用いてLike/Nopeを実行する。各操作間にランダム遅延を適用。 | 入力: キートリガー、遅延秒数<br>出力: 次カードへの遷移 |
| **FR-04** | **動的ポップアップ・マッチ検知** | スワイプ中に突発的に出現する「It's a Match!」や「Add to Home Screen」等のモーダルを検知し、安全に閉じる。 | 入力: モーダル要素<br>出力: スワイプ処理への復帰 |
| **FR-05** | **上限到達検知・安全終了** | 無料Like上限モーダル（「You're Out of Likes」等）または「No More Profiles」を検知した場合、ループを脱出して結果をログ出力後ブラウザを閉じる。 | 入力: 上限モーダル検知<br>出力: 実行結果サマリー、セッション終了 |

## 3. 非機能要件 (Non-Functional Requirements)

### 3.1 信頼性・耐障害性
- **ElementClickInterceptedException の防止**:
  - カードが切り替わる途中やオーバーレイが存在する場合のクリック干渉を回避するため、キーボードイベント（`send_keys(Keys.ARROW_RIGHT)`）を優先活用する。
- **StaleElementReferenceException の防止**:
  - プロファイルカードはスワイプごとにDOMから破棄・生成されるため、カード要素の参照を保持し続けず、ルート要素（`body`）に対する操作を主体とする。

### 3.2 人間動作模倣 (Anti-Bot)
- 各スワイプ操作間に `random.uniform(1.2, 3.0)` 秒のゆらぎを持たせる。

## 4. 主要数値・境界値・データ制約

### 4.1 主要数値パラメータ
| パラメータ | 規定値 | 備考 |
| :--- | :--- | :--- |
| **画面解像度** | `1080 x 1920` (Mobile) または `1280 x 800` (PC) | UI要素の折りたたみ・配置崩れ防止 |
| **スワイプ間隔** | `1.2 - 2.8` 秒 (ランダム) | 機械的判定（Rate Limit）回避 |
| **最大スワイプ試行回数** | `50 - 100` 回 (安全上限) | 1日の無料Like枠上限に配慮 |
| **要素待機タイムアウト** | `10` 秒 | 初期ローディングおよびモーダル検知用 |

### 4.2 考慮すべき境界値・例外エラー
1. **Like上限（Out of Likes）**:
   - 課金ポップアップが表示された時点で操作を受け付けなくなるため、これを終了シグナルとして捉える。
2. **候補枯渇（There's no one new around you）**:
   - スワイプ対象のカードが存在しない状態を検知し、クラッシュせず終了する。
3. **マッチ成立モーダル**:
   - マッチ画面で背面クリックが無効化されるため、「Back to Tinder」ボタンを特定して閉じる。

### 4.3 データの制約
- **認証セッションの保持**:
  - SMS認証やGoogleログイン等の2要素認証（2FA）を自動で突破することはCAPTCHAやセキュリティ規約に抵触するため、ユーザープロファイル（Chrome Profile）を引き継ぐか、初回手動ログイン後のセッション利用を前提とする。

## 5. テスト仕様・受入基準

1. **画面到達受入**:
   - 初期アクセス後、ログイン完了状態からスワイプ可能なメイン画面が表示されること。
2. **スワイプ動作受入**:
   - Like（右矢印）がランダムな間隔で連続実行されること。
3. **ポップアップ回避受入**:
   - スワイプ途中でマッチ画面や案内ポップアップが出現してもスクリプトが停止せず、閉じて処理を継続できること。
4. **安全停止受入**:
   - Like上限またはプロファイル枯渇を検知した際、例外エラーで落ちずにクリーンにブラウザを終了すること。
