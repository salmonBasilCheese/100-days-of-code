# システム要件定義書: Billboard Hot 100 to YouTube Music Playlist Generator

## 1. システム概要
### 1.1 目的
本システムは、ユーザーが指定した任意の日付（`YYYY-MM-DD`）における米Billboard Hot 100チャートをスクレイピングし、取得した全100曲の楽曲リストを基に、YouTube Music上に同タイトルのプレイリスト（`YYYY-MM-DD Hot 100`）を自動作成して楽曲を一括登録することを目的とする。

### 1.2 背景・スコープ
- **背景**: Spotify Web APIの仕様変更（有料会員限定化・開発者権限の厳格化）に伴う代替策として、無料のGoogleアカウントで利用可能なYouTube Music（`ytmusicapi`）を採用し、自律的なプレイリスト構築フローを実現する。
- **開発スコープ**:
  - ユーザー入力日付のバリデーション
  - Billboard Hot 100チャートのスクレイピング（曲名・アーティスト名抽出）
  - YouTube Music API（`ytmusicapi`）を用いた認証および楽曲検索
  - 新規プレイリストの作成および楽曲追加
  - 例外処理（検索ヒットなし、レートリミット対策、通信エラー）の網羅

## 2. 機能要件 (Functional Requirements)

| 機能ID | 機能名 | 詳細説明 | 期待される入力 / 出力 |
| :--- | :--- | :--- | :--- |
| **FR-01** | **日付入力・検証機能** | ユーザーから `YYYY-MM-DD` 形式で日付入力を受け付け、有効な日付か（過去の実在日付かつHot 100創設以降か）を検証する。 | 入力: 日付文字列<br>出力: 検証済み `datetime.date` オブジェクト |
| **FR-02** | **Billboard スクレイピング機能** | 対象日付のBillboard Hot 100ページへリクエストを送信し、全100曲の曲名（およびアーティスト名）を抽出・整形する。 | 入力: 検証済み日付<br>出力: 楽曲情報辞書/タプルのリスト（100件） |
| **FR-03** | **YouTube Music 認証機能** | `ytmusicapi` を用いて、ローカルに保持した認証情報（OAuthまたはブラウザヘッダー情報）によりYouTube Musicクライアントを初期化する。 | 入力: 認証構成ファイル（`oauth.json`等）<br>出力: 認証済みYTMusicインスタンス |
| **FR-04** | **楽曲検索・ID解決機能** | 抽出した曲名とアーティスト名をクエリとしてYouTube Music内を検索し、最も関連性の高いトラックの `videoId` を取得する。ヒットしない場合はスキップログを出力する。 | 入力: 楽曲名・アーティスト名<br>出力: `videoId` のリスト（最大100件） |
| **FR-05** | **プレイリスト作成・登録機能** | プレイリスト名「`YYYY-MM-DD Hot 100`」を作成し、解決された `videoId` 群を一括追加する。 | 入力: プレイリスト名、`videoId` リスト<br>出力: 作成されたプレイリストURL / ID |

## 3. 非機能要件 (Non-Functional Requirements)

### 3.1 信頼性・耐障害性
- **403 Forbidden 対策**:
  - Billboardサイトへのアクセス時、標準のRequests User-Agentが遮断されるため、ブラウザと同等の `User-Agent` リクエストヘッダーを必ず付与すること。
- **HTTP例外ハンドリング**:
  - `requests.exceptions.RequestException` を適切に捕捉し、通信障害発生時にログを出力して安全に終了すること。
- **楽曲未検出時の堅牢性**:
  - 特定の古い楽曲や別バージョン等でYouTube Music検索結果が0件の場合、例外（`IndexError` 等）で停止させず、Warningログを出力して次の楽曲へフォールバックすること。

### 3.2 性能・運用制約（Rate Limit対策）
- **アクセス間隔の制御**:
  - YouTube Musicに対する短時間の過剰リクエスト（100件連続検索）による一時ブロック（HTTP 429 Too Many Requests）を防ぐため、1曲検索ごとに **0.5〜1.0秒のウェイト（`time.sleep`）** を挟むこと。
- **タイムアウト設定**:
  - スクレイピングリクエストには `timeout=15` 秒を設定すること。

### 3.3 セキュリティ・機密情報保護
- **認証ファイルの隔離**:
  - `ytmusicapi` の認証ファイル（`oauth.json` や `browser.json` 等）は機密トークンを含むため、**`.gitignore` に必ず除外指定**し、リモートリポジトリへの流出を防止すること。

## 4. データ仕様・制約

### 4.1 主要数値・パラメータ
| 項目 | 設定値 / 境界値 | 備考 |
| :--- | :--- | :--- |
| **対象URLパターン** | `https://www.billboard.com/charts/hot-100/{YYYY-MM-DD}/` | Billboardアーカイブ |
| **日付許容範囲（下限）** | `1958-08-04` | Billboard Hot 100 開始日 |
| **日付許容範囲（上限）** | 実行時点の「今日」まで | 未来日付は不可 |
| **期待取得件数** | `100` 件 | チャートの総曲数 |
| **検索リクエスト待機時間** | `0.5` 〜 `1.0` 秒 | APIレート制限保護 |
| **プレイリスト命名規則** | `"{YYYY-MM-DD} Hot 100"` | 例: `2000-08-12 Hot 100` |

### 4.2 文字列クレンジング仕様
- **曲名・アーティスト名**:
  - HTML内の余分な空白文字、タブ文字、改行コード（`
`, `	`）を `.strip()` で完全除去。
  - 特殊文字（`&amp;` やアクセント記号）の正規化。

## 5. テスト仕様・受入基準 (Acceptance Criteria)

1. **日付バリデーション検証**:
   - `1958-08-03`（創設前日）および未来日を入力した際、エラーメッセージが表示され再入力を要求すること。
   - `invalid-date` や `2023-02-30` などの不正文字列を検知して弾くこと。
2. **スクレイピング検証**:
   - Billboardから厳密に100曲分の楽曲データが抽出されること。
3. **認証・作成検証**:
   - YouTube Music上に `YYYY-MM-DD Hot 100` という名称のプレイリストが新規生成されること。
   - 解決できた楽曲がプレイリスト内に正しく登録され、YouTube Music UI上で再生可能であること。
4. **セキュリティ検証**:
   - `git status` で `oauth.json` 等の認証ファイルが追跡対象外になっていること。
